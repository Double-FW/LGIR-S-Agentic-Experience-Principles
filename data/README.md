# Canonical data and record boundaries

- framework.json owns names, the five principle definitions and the attributed owner-supplied robustness definition.
- criteria.json owns the 25 candidate criteria, priority labels, applicability, approaches, probes, failure examples and source/case/technique references.
- examples.json owns the eight fictional case narratives.
- sources.json owns the inspected source register and scope qualifications.

The renderer derives SPECIFICATION.md, understanding/, the example case pages/index and implementation/techniques.md. Edit the canonical records and regenerate these views. Other implementation/evaluation/governance documents are independently authored and need coordinated editorial maintenance.

All criterion product results start not_evaluated. A candidate requirement, a written probe and a generated expected observation do not constitute a real assessment. Preserve authority, tier status, source identity and limitations when extracting records for retrieval or future datasets.

Operation examples are separate synthetic demonstration records governed by their local schema. They do not authorise actions, implement a state machine or establish provider guarantees. Local record validation checks only stated structural/invariant conditions.

This package has no embedding service, model training, deployed agent, credentials, GitHub publication or Hugging Face sync. Machine-readable content is supplied for inspection and implementation planning, not as evidence of those operations.
